# 2026-11-07 23:00 — 修复 Wi-Fi 配网密钥错位，明确蓝牙回退方式

- `DeviceLink.configureWiFi` 改为「先发 USB 配置、等设备回 `wifi` 状态后再保存本机密钥」：
  旧顺序先写 `passportLANHost/Key` 再发串口，设备一旦回 `config_error`，Mac 与设备会永久使用不同密钥，
  表现为设备已经入网（mDNS 可解析、8765 可连）但 TLS-PSK 一直被重置。
- 新增 `WiFiProvisioningAck` 纯函数和单测：`config_error` / `network_error` 拒绝；`connecting` / `ready` /
  `auth_error` / `not_found` 且 host 匹配或首次配网 host 为空时确认。配网 4 秒没确认不写密钥并提示重试。
- `WiFiClient` 增加 `onConnectFailure`；`DeviceLink` 在设备报告 `wifi stage=ready`、但 TLS 连续失败 5 次后置
  `wifiHandshakeFailed`，设置页显示「设备已入网，但加密握手失败」，并提示重新输入 Wi-Fi 密码，或用
  「清除 Wi-Fi 配对」让设备回到蓝牙。
- `updateBluetooth` 不再让残留的 USB 串口永久压住蓝牙：串口打开 6 秒仍未握手视为残留节点 / 设备无响应，
  允许 BLE 接管；心跳每 5 秒重算一次。解决「拔线后 USB 节点还在，Wi-Fi 又失败，蓝牙也不出现」。
- 原因：设备固件在配过 Wi-Fi 后会 `esp_bt_mem_release(ESP_BT_MODE_BLE)`，BLE 不再作为备用链路；
  Wi-Fi 密钥错位时只能靠 USB 恢复。本次不改固件，先把 app 侧的错位根因和可见性修掉。
- 验证：`DeviceProtocolTests` 30 项通过；`update-strings.sh` 构建通过，670 条字符串。真机 Wi-Fi 重配与
  拔线切换待用户用 USB 重新保存一次 Wi-Fi 后验证（设备端 BLE 回退需要改固件，未在本次改动）。
